# ADR 0001: Contract freeze for the pilot

- Status: **PROPOSED**, needs CTO approval
- Date: 2026-11-09
- Deciders: Global CTO (approver); Payments Engineering, Financial Engineering, Integrations (reviewers)
- Related: [OPEN_QUESTIONS.md](../OPEN_QUESTIONS.md) Q1 to Q4

## Context

The founder specs disagree on several contract basics. Until we choose, the
OpenAPI contract, database schema and state machine cannot be written. This ADR
proposes one answer for each and cites the conflict. Anything still marked
**open** here is not decided; code must follow this ADR's proposal and
`OPEN_QUESTIONS.md` tracks the question.

## Decisions

### 1. Gates follow the Master Register

Gate meanings differ between documents. 01-05 (Business Requirements) uses
G0 Legal, G1 Architecture, G2 Partners, G3 Security, G4 Finance, G5 Reliability,
G6 QA, G7 Go-live. The v3.0 Gap Analysis uses G0 Governance … G7 Customer
transparency. 01-09 (System of Record) settles it: "G0–G7 gates in the approved
master register control production, not conflicting historical gate-count
descriptions."

We use the Master Register definitions:

| Gate | Meaning |
|---|---|
| G0 | Authority and funds flow |
| G1 | Scope and architecture |
| G2 | Provider and security scope |
| G3 | Financial correctness |
| G4 | Integration and reconciliation |
| G5 | Security, resilience and operations |
| G6 | Merchant pilot launch |
| G7 | Expansion by cell, rail and product |

### 2. State names come from 06-01

PaymentIntent, attempt, operation-resolution and refund status names are the
06-01 sets, verbatim, uppercase in code and the database, lowercase on the wire.

Known differences, all resolved in favor of 06-01:

- 01-03 (Glossary) also uses `CREATED`, `CAPTURED` and `AUTHORIZED` as intent
  states. They are not intent states. `AUTHORIZED` is an attempt status.
- 04-01 (Public API standards) shows `requires_action`. The 06-01 name is
  `requires_customer_action`.
- 04-01 shows both `cancelled` and `canceled`. We use `canceled` (American
  spelling, 06-01).

### 3. Money on the wire: decimal-string minor units

`amount_minor` is a base-10 string of a signed integer, for example `"1999"`,
plus an ISO 4217 `currency`. JSON numbers for money are rejected with 400.

Sources: 02-05 ("signed integer minor units encoded as a decimal string …
serialized to JSON as a string for cross-language safety … reject JSON
fractional/float money values") and 02-06 examples. **Conflict:** 02-01 (PRD),
01-05, 01-09 and 04-10 examples show `"amount_minor": 12500` as a JSON integer.
02-05 is the money authority, so this ADR follows it. See Q1.

In memory and in PostgreSQL, the pilot uses `int64` / `BIGINT`. **Conflict:**
02-05 says `NUMERIC(38,0)`. `int64` covers ±9.2 × 10¹⁸ minor units, far beyond
any pilot amount, and the API rejects anything outside a configured maximum.
See Q2.

### 4. URLs are snake_case

04-01: "lowercase plural nouns in snake_case: /payment_intents, /refunds,
/webhook_endpoints". **Conflict:** 01-03, 02-01, 02-02 and 02-07 examples use
kebab-case (`/payment-intents`, `/payment-operations`). 04-01 is the API
standard, so we use snake_case. Spectral enforces it
(`api/openapi/.spectral.yaml`, rule `zp-paths-snake-case`).

### 5. Go for every backend module in the pilot

All four deployables and all nine bounded contexts are Go 1.26, one Go module
(`github.com/zoiko/zoikopay`). The specs treat technology examples as
non-binding ("reference implementations", 03-03).

### 6. Resource ID prefixes

Public IDs are a type prefix plus an opaque, URL-safe suffix generated by
the server (a UUIDv7, so IDs sort by creation time). Clients must treat the
suffix as opaque.

| Prefix | Resource | Spec usage |
|---|---|---|
| `pi_` | PaymentIntent | Consistent in 12 specs (01-03, 02-01, 04-01, 04-06, 06-01 …) |
| `op_` | Payment operation (capture, cancel, refund attempt …) | Consistent in 14 specs (02-07, 04-08, 06-01 …) |
| `re_` | Refund | **No spec defines a refund prefix**; proposed here |
| `mer_` | Merchant | Used by seven specs, including 06-01 and 04-06. **Conflict:** 04-03 uses `mrch_` (Q10) |
| `ten_` | Tenant | **Proposed**, not yet frozen: spec examples only (`ten_example_01`, `ten_demo`). First built by BC-01 `merchant.tenants` (Q15) |

Other prefixes in spec examples (`evt_` events, `req_`
request IDs, `cell_` regional cells) are recorded in Q10 and decided when the
resource is first built.

## Consequences

- The OpenAPI contract (M2) can be written against fixed names, encodings and paths.
- If the CTO picks JSON-integer money or NUMERIC(38,0), the `money` package
  (M1) and the contract change before M2 freezes them; nothing after M1 depends
  on the wire encoding directly.
